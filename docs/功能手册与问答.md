## 一、这玩意儿到底能干什么

**第一句大白话：它不是聊天框，是一个能动手的本地助手。**

你在网页里跟它说话，它不只是回你一段文字。它可以在你这台电脑上读文件、写文件、跑命令、开浏览器、改配置，甚至隔着一根数据线去操作你的手机。普通的网页版 AI 只能"告诉你怎么做"，这个能"替你做"。代价是它拿到的是你这台机器的权限——所以它只监听本机（`127.0.0.1`），也绝不建议你把它放到公网上。

**第二句大白话：随身卡解决的是"换台电脑还能用"。**

这类工具最烦的地方是配置里塞满了绝对路径，比如 `C:\Users\你\AppData\...\node.exe`。你把整个目录拷到 U 盘、插到另一台电脑，盘符从 `E:` 变成 `F:`，所有路径立刻失效，工具列表一个个变红。随身卡的做法很土但很有效：**每次启动前先跑一遍 `portable/portable-repath.mjs`，把配置里的路径按当前盘符重写一遍**，然后再启动本体。所以你在哪台 Windows 上双击，它都能自己校准，你不需要改任何文件。

**第三句大白话：手机操控和抖音自动化，解决的是"让它真的去点"。**

手机操控这边，它靠 ADB 连上你的手机，截图、看屏幕、点按钮、打中文——"看"交给视觉模型，"点"交给系统控件坐标，原因是纯靠看图估坐标会偏几十像素，点了等于没点。抖音这边反过来：它不给抖音造接口、也不模拟登录，而是**接管你自己已经登录的那只浏览器**（走调试端口 9222），因为网页接口带签名和设备指纹，无头浏览器一眼就被认出来，只有你自己的浏览器最真实。

**最后一句：控制台解决"不用敲命令"。**

一套东西七八个服务、十几个端口，全用命令行启动对新手是灾难。所以仓库里有两个图形入口：`start-gui.bat`（新手启动器，3400 端口，带环境体检和一键启动），和 `console/`（控制台，3300 端口，管服务启停、看日志、开关模块、填 Key）。你双击、点几下就行。

## 二、十分钟上手（从零到跑起来）

先明确一件事：这个仓库是**源码仓**，本身不是一个能直接跑的"卡"。真正能跑的那份叫「随身卡」，目录结构见 [六、附录](#六附录)。所以下面分两条路。

### 路线 A：你手上已经有一张随身卡

这一步最快，全程只需要双击。

| 步骤 | 做什么 | 会看到什么 | 成功标志 |
| --- | --- | --- | --- |
| 1 | 把卡插到电脑上，打开 `<卡>:\DSH\` 目录 | 里面有 `start-dsh.bat`、`start-all.bat`、`node\`、`dsh-workspace\`、`.dsh\`、`workspace\` | 这几个目录都在，不是空的 |
| 2 | 双击 `start-dsh.bat` | 一个黑窗口，开头打印 root、DSH_HOME 两行路径 | 没有立刻消失，窗口停在那里刷日志 |
| 3 | 等 10～60 秒（USB 卡首次启动会慢） | 日志里出现本地地址，通常是 `http://127.0.0.1:3080` | 浏览器打开这个地址能看到界面 |
| 4 | 如果地址后面带 `?token=...`，把**整条地址**复制到浏览器 | 界面正常加载，不再是 401 | 能看到对话界面 |
| 5 | 双击 `start-all.bat`（可选） | 先弹出控制台窗口（3300），再弹 DSH 窗口 | 浏览器打开 `http://127.0.0.1:3300` 能看到控制台 |

> 想更省事：仓库根（或卡根）如果有 `start-gui.bat`，直接双击它。它会在 3400 端口开一个"新手启动器"网页，帮你体检、填 Key、一键启动，不用记任何命令。

**第一次必须做的一件事：填 Key。** 没有 Key 也能打开界面，但助手说话会失败（模型调不通）。填的位置有两个：

- 新手启动器第 2 步「填 Key · 选模块」；
- 或者控制台 3300 的「⚙️ 模块开关 & API 配置」面板右列。

填完点保存，然后**重启一次 DSH**（控制台操作栏的「🔁 重启 DSH」），新 Key 才会被带上。

### 路线 B：你只有这份仓库

这条路要自己准备运行环境。别怕，一共就四步。

**第 1 步：确认有没有 Node。**

打开一个终端（Win+R 输入 `cmd` 回车），敲：

```bat
node -v
```

- 看到 `v22.x.x` 或更高：可以了，跳到第 3 步。
- 看到"不是内部或外部命令"：去装 Node。到 nodejs.org 下 LTS 版本（安装时一路下一步即可），装完**关掉终端重新开一个**再验一次。

**第 2 步：把仓库放好。**

```bat
cd /d D:\你的目录\dsh-portable-kit
```

**第 3 步：跑一次自检，看它缺什么。**

```bat
node portable\portable-verify.mjs
```

它会打印 8 组检查结果。这里**在源码仓里跑，本来就会有一堆警告**——因为这个仓库没有 `.dsh\`、没有 `node\`、没有 `dsh-workspace\`，那些是随身卡才有的。自检的价值是告诉你"缺哪几样"，不是让你在仓库里跑起来。

**第 4 步（可选）：只想起控制台看看。**

```bat
node console\server.mjs
```

然后浏览器打开 `http://127.0.0.1:3300`。注意：仓库里没有 `.dsh\profiles`，所以控制台里的"模块开关"只会写清单文件，**不会真的去改配置**——这是设计好的安全闸，免得你在源码仓里误改另一份安装。

**想真正跑起来，还得补齐这三样**（从你已有的随身卡或另一份安装里拷）：

- `node\`：整个 Node 运行时目录（含 `node.exe`）；
- `dsh-workspace\`：DSH 本体的运行目录；
- `.dsh\`：配置目录，至少要有一个 `profiles\` 子目录。

三样都摆到仓库根（或卡根），再双击 `start-dsh.bat`。

### 两条路共同的"第一次"清单

- [ ] 电脑是 64 位 Windows 10 / 11（32 位不支持）。
- [ ] 防火墙弹窗时允许 Node 监听本地端口。
- [ ] 杀毒软件如果对 `node\` 里的 `node.exe` 报"未知程序"，加白名单放行。
- [ ] 浏览器用 Edge 或 Chrome（其它浏览器没测过）。
- [ ] 卡是 exFAT 就记住：没有权限控制，别在公共电脑上开。

## 三、功能逐项详解

每个功能都用同一套五段式写：**它是什么 → 解决什么痛点 → 怎么用 → 你会看到什么 → 坑与边界**。

### 1. 便携卡运行时（`start-dsh.bat` / `start-all.bat`）

**它是什么**
`portable\start-dsh.bat` 是主启动器，一个几十行的批处理文件。它做七件事，顺序不能乱：记住自己所在的目录（`ROOT=%~dp0`）→ 设 `DSH_HOME` 指到卡上的 `.dsh` → 把卡上的 `node\` 塞到 `PATH` 最前面 → 设 `NODE_PATH` → 跑一遍 `portable-repath.mjs` 校准路径 → `cd` 到 `workspace` → 用卡上的 Node 启动 DSH。

`portable\start-all.bat` 是它的"加量版"：先最小化拉起控制台（如果 `workspace\启动控制台.bat` 存在，等 3 秒），再 `call` 一次 `start-dsh.bat`。

**解决什么痛点**
不这么干的话，你每次换电脑都得手工改配置文件里的盘符和用户目录；漏改一处，某个 MCP 工具就启动失败（典型报错是 `ENOENT`，意思是"文件不存在"）。而且插件里有些地方是直接裸调 `node` 的，`PATH` 不前置就会跑到系统那个旧版本上，版本不对又是一堆玄学错误。

**怎么用**

- 正常启动：双击 `start-dsh.bat`。
- 想换端口：`start-dsh.bat --port 3081`。这个文件会把参数原样透传给 DSH，所以 DSH 支持的启动参数都能用。
- 想连控制台一起起：双击 `start-all.bat`（参数同样透传）。
- 手动指定环境变量再启动（很少需要）：

```bat
set DSH_HOME=E:\DSH\.dsh
set DSH_WORKSPACE=E:\DSH\workspace
E:\DSH\start-dsh.bat
```

**你会看到什么**

```
============================================
  DeepSeek Harness - portable
  root     : E:\DSH
  DSH_HOME : E:\DSH\.dsh
============================================
```

接着是 repath 的五行输出，然后是 DSH 自己的启动日志，最后打印本地地址。你把这个黑窗口关掉的那一刻，DSH 就停了，浏览器页面会连不上——这是正常的，不是崩溃。

退出时窗口会打印 `[dsh exited with code 0]` 并停住等你按键，方便你看最后几行日志。

**坑与边界**

- 前置检查有三道，任何一道不过都会打印 `[X]` 并停住：找不到 `node\`、找不到 `dsh-workspace\...\bin.js`、找不到 `.dsh\`。看到 `[X]` 就说明文件没拷全，别硬撑着重启。
- repath 失败**不会**阻止启动，只打一行警告。所以如果你发现工具红了但窗口能开，多半就是 repath 的结果不对，手动跑一遍看输出。
- 卡是 U 盘/SD 卡时，首次启动慢 10～60 秒是正常的（要读几万个插件小文件），别以为卡死了。
- 运行中不要拔卡。
- `start-all.bat` **不会**帮你起 QQ 桥接、SnowLuma 和语音引擎——那三个是需要各自窗口的常驻服务，得从 `workspace\` 里各自的 `.bat` 起，或者在控制台点「一键启动」。

### 2. `portable-repath.mjs`（路径校准器）

**它是什么**
`portable\portable-repath.mjs`，150 行左右，是整个"便携"的核心。它只改两处文件：

1. `cordis.patch.yml`（DSH 的配置补丁文件）里所有 `command: '...\node.exe'` 换成当前卡的 node；所有 `args: ['...\mcp-xxx.js']` 换到 `<卡>\workspace\qq-bridge\src\mcp-xxx.js`。
2. `package.json` 里三个依赖固定改成相对路径写法 `file:../../...`（`dsh-screen`、`qq-agent-presets`、`qq-mode-console`）。

**解决什么痛点**
MCP 工具的启动命令必须是绝对路径，绝对路径一换盘就废。既然没法用相对路径，那就只能"存一份可以被重写的，每次启动前校准一次"。这不是优雅方案，是唯一能用的方案。

**怎么用**

```bat
node portable\portable-repath.mjs           :: 真改
node portable\portable-repath.mjs --check   :: 只检查，不写盘
node portable\portable-repath.mjs --force   :: 强制对当前栈动手（危险，见下）
```

**你会看到什么**

```
[repath] root      = E:\DSH
[repath] DSH_HOME  = E:\DSH\.dsh
[repath] node      = E:\DSH\node\node.exe (ok)
[repath] yml: 改写 3 行
[repath] package.json: already portable
[repath] 已更新: cordis.patch.yml (3 行)
```

第二遍再跑，应该是 `yml: already portable` + `package.json: already portable` + `无需改动`——**这就是幂等**：值没变就不写盘，`git diff` 永远是干净的。有 `--check` 时最后一行会写 `--check 模式，未写盘`。

**坑与边界**

- **安全闸**：如果脚本所在目录没有 `.dsh\profiles`，又没加 `--force`，它会直接停下并返回退出码 2，打印大意是"本栈没有 profiles 目录，跳过"。如果你环境里还设了 `DSH_HOME`，它会额外提示"那指向另一份安装，本脚本不会去改它"。这是故意的：防止你在一份代码仓里误改掉另一份真正在用的安装。
- 它只管"路径"，不管"内容"。你在 yml 里手写的其它配置它不会碰。
- 它不会创建缺失的文件。yml 不存在就什么都做不了。

### 3. `portable-verify.mjs`（8 组自检）

**它是什么**
`portable\portable-verify.mjs`，一个只读的体检脚本，跑完给结论，不改任何东西。

**8 组分别查什么**

| # | 组名 | 查的内容 |
| --- | --- | --- |
| 1 | 运行时 | `node\node.exe` 在不在，`node -v` 跑不跑得动 |
| 2 | DSH 主体 | `dsh-workspace\...\dsh\lib\bin.js`、`.dsh\profiles\web`、`cordis.patch.yml`、`package.json`、`workspace` 目录 |
| 3 | 路径可移植性 | yml 和 package.json 里有没有写死 `C:\Users\<名字>\dsh-workspace` 这类路径；yml 里第一条 `command:` 是不是本栈的 node |
| 4 | QQ 插件 | `qq-agent-presets`、`qq-mode-console` 有没有实体入口文件、**是不是符号链接**；`@deepseek-ai\schemastery` 在不在 |
| 5 | 记忆 / 人格 | 共享记忆主文件（`workspace\shared\` 下那份 Markdown）非空、人格卡文件非空、桥接人格文件、记忆数据库、凭据文件 |
| 6 | 语音 | 读 `portable-strip.txt`；如果声明了要裁掉语音，就检查 `gpt-sovits\`、`rvc\` 和 yml 里是不是真的没有语音 MCP 了 |
| 7 | exFAT 兼容 | 递归扫符号链接和硬链接（跳过 `node_modules`、`.git`，深度超 6 层就停） |
| 8 | 本机环境 | 打印当前盘符、系统盘、用户名、`DSH_HOME`——纯信息，不判定 |

**解决什么痛点**
"插到别人电脑上才发现不对"是最贵的错误。这组检查就是提前把能想到的坑全踩一遍：路径写死了、插件是符号链接（exFAT 上会失效）、语音声明了裁掉但文件还在、记忆文件空了。

**怎么用**

```bat
node portable\portable-verify.mjs
```

**你会看到什么**
绿色的 OK、黄色的 WARN、红色的 FAIL 三类行，末尾一句总结。退出码有三种：

| 退出码 | 含义 | 你该做什么 |
| --- | --- | --- |
| `0` | 全部通过 | 直接插到别的电脑上用 |
| `1` | 有关键项失败 | **还不能**插到别的电脑上用，按 FAIL 那行的提示修 |
| `2` | 只有警告 | 关键项过了，警告按需处理（比如没配凭据文件） |

**坑与边界**

- 在**源码仓**里跑，几乎必然有一堆 FAIL 和 WARN——这个仓库本来就不含 `.dsh`、`node`、`dsh-workspace`。它的正确用法是在**卡上**跑。
- 第 7 组扫描会跳过 `node_modules`，所以它不会因为依赖目录里的符号链接误报；反过来说，`node_modules` 里的链接它查不到。
- 它不改任何文件，所以"跑完了问题还在"是正常的，你得按提示动手。

### 4. `sync-to-card.ps1`（把电脑上的记忆同步到卡）

**它是什么**
`portable\sync-to-card.ps1`，一个 PowerShell 脚本，用 `robocopy` 把"你这台电脑上产生的数据"单向拷到卡上。

**同步哪些东西**

| 内容 | 说明 |
| --- | --- |
| 抖音浏览记忆、状态、私信分享回执 | 不含那个约 475MB 的浏览器 profile 目录 |
| `.dsh\sessions`、`.dsh\storages` | 会话记录和存储 |
| `.credentials.yaml`、用量统计、`cordis.patch.yml`、`package.json` | 凭据与配置 |
| `workspace\shared`、`workspace\qq-bridge\roles` | 共享记忆和人格文件 |

`robocopy` 的公共参数是 `/E /COPY:DAT /DCOPY:DAT /R:1 /W:1 /XO /NFL /NDL /NJH /NJS /NP /MT:4`。其中 **`/XO` 是重点**：只复制"比卡上更新"的文件，卡上更新的文件不覆盖。这样你在卡上刚改过的东西，不会被电脑上的旧版本盖掉。

**解决什么痛点**
你平时在台式机上用，出门带卡。聊天记忆、浏览记录、人格文件都在机器上，不同步过去，插到笔记本上就是"失忆"状态。

**怎么用**

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File E:\DSH\sync-to-card.ps1 -CardRoot E:\DSH
```

**你会看到什么**
先是 `robocopy` 自己的表格输出（每个目录几行），最后几行是 repath 的输出，以及一句总结。`robocopy` 的退出码小于 8 都算正常，8 以上才报 WARN。

**坑与边界**

- **只往卡写，不删机器上的东西**，也不会删卡上多出来的文件。
- 脚本结尾会用卡上的 node 再跑一次 `portable-repath.mjs`，**顺便重新应用一遍 `portable-strip.txt`**。这一步是必要的：不然同步把 yml 覆盖回去，你之前关掉的模块又回来了。
- 卡没插好或路径写错，第一行就会打印 `[X] ... not found` 并退出。
- 同步会在卡上留下你机器上的凭据文件（明文）。这张卡别借人。

### 5. `portable-strip.txt`（声明式裁剪：一行关一个模块）

**它是什么**
一个纯文本清单，**要放在 `portable-repath.mjs` 所在的那一层目录**（随仓库时是 `portable\` 下，在卡上是 `DSH\` 根）。一行写一个"要整块删掉的配置 id 前缀"，`#` 开头是注释。repath 每次启动都会读它，把 yml 里对应的整段配置摘掉，并在原位留一行注释：

```yaml
# [portable] 已按 portable-strip.txt 移除: mcp-tts-voice-7
```

**解决什么痛点**
随身卡为了瘦身，把 34.4GB 的语音模型删了。但配置里还留着语音 MCP，启动时它会去找一个不存在的模型，报错、拖延启动。手动删 yml 又很危险（格式复杂、容易删错缩进）。声明式清单的好处是：**改一行文本就行，剩下的交给脚本，而且每次启动都会重新应用**。

**怎么用**

1. 用记事本打开**和 `portable-repath.mjs` 同一个目录**里的 `portable-strip.txt`（在卡上就是 `DSH\` 根）。
2. 加一行，比如 `mcp-web-search-safe`（关掉联网搜索）。
3. 保存。
4. 重启 DSH（关掉黑窗口再双击 `start-dsh.bat`，或控制台点「🔁 重启 DSH」）。

**你会看到什么**
重启后 repath 那行会变成类似 `yml: 改写 2 行，移除 1 个条目 (mcp-web-search-safe)`，yml 里对应段落变成一行 `# [portable] 已按 ... 移除:` 注释。DSH 的工具列表里那个工具消失了。

**坑与边界**

- **幂等**：同样的清单跑一百遍，结果都一样。已经删过的段落不会重复处理（因为它已经是注释了）。
- 写的是**前缀**，不是精确 id。写 `mcp-snowluma` 会把 `mcp-snowluma` 和 `mcp-snowluma-host` 一起删掉——想要只删一个，就写更长的那个。
- **改完必须重启 DSH**。清单只在启动时被应用，运行中的进程不会热加载。
- 恢复某个模块：把那一行删掉或注释掉，重启即可。
- 图形化的开关（控制台或启动器里的勾选框）**会整个重写这个文件**。你手工加的注释会被覆盖掉，别把重要说明写在这里。
- 两个图形入口各自按「自己所在的目录」去找这份清单（启动器在 `launcher\` 的上一层，控制台在 `console\` 的上一层）。所以手工编辑时，认准 `portable-repath.mjs` 旁边那一份，别在几处各改一半。

### 6. 本地控制台（3300）

**它是什么**
`console\server.mjs` + `console\index.html`，一个跑在本机的网页控制台，管着这一整套服务。启动方式：

```bat
node console\server.mjs
```

然后浏览器开 `http://127.0.0.1:3300`。

**页面上有什么**（顶部写着「本机一键管理 · 启动/停止/看日志 · 这个窗口别关」）

- **五张状态卡**：DSH 界面服务（3080，带「打开 DSH」按钮）、SnowLuma（5099，QQ 网关，可启动/停止/重新注入 QQ）、QQ-Bridge（3100，显示模式、人格、DSH 通道、SnowLuma 连接状态）、机器人 QQ 账号（昵称、QQ 号、白名单群、白名单好友）、GPT-SoVITS 语音引擎（9880）。
- **API 通道（官方 / 中转）面板**：填中转地址和 Key，四个按钮「保存中转配置 / 测试当前通道 / 切到官方 / 切到中转」。切换会短暂重启桥接（几秒）。
- **⚙️ 模块开关 & API 配置面板**：见下一节。
- **操作栏**：🚀 一键启动、🔄 重启桥接、⏹ 停止桥接、🔁 重启 DSH、📨 唤醒并处理未读，外加三个跳转链接。
- **一键启动进度**：7 个步骤（QQ 客户端 → SnowLuma → QQ 注入 → QQ-Bridge 连接 → GPT-SoVITS API → 语音暖场 → 通道代理），带百分比进度条。
- **桥接详情、相关进程、日志（两个 tab）、🔑 登录密钥**（默认打码，每一项都有 👁 显示和 📋 复制）。

**解决什么痛点**
以前要开五六个黑窗口、记五个端口、按顺序启动。现在一个页面全看完，还能看日志——出问题时不用猜"到底是哪一步挂了"。

**怎么用（几个最常用的）**

- 起全套：开控制台 → 点「🚀 一键启动」→ 看进度条走完 7 步。控制台**不做开机自启**，需要时手动点。
- 只重启 DSH（改了模块开关之后）：点「🔁 重启 DSH」。它会先确认 3080 端口的占用者**确实是 node 且命令行里带 dsh**，否则中止，不会乱杀进程。然后等端口释放（最多 15 秒）、拉起新的 DSH（最多等 60 秒）、从日志里抓新的带 token 地址，必要时帮你用新地址重开浏览器。
- 看日志：日志面板两个 tab，一个桥接、一个 SnowLuma，可调行数（10～2000 行）。
- 唤醒未读：点「📨 唤醒并处理未读」，让机器人把所有会话的积压消息过一遍。

**你会看到什么**
状态卡上会显示"运行中 / 未运行"和端口号；日志面板会滚动刷新；一键启动时进度条一格一格往前走，某一步失败就停在那一步并显示原因。

**坑与边界**

- **控制台永不主动停 DSH**，卡片上也这么写着；要重启 DSH 只能用操作栏的按钮。
- 「重启桥接」期间会断开约 5～15 秒，这期间的消息可能漏回，确认框里写了。
- 所有接口**没有登录鉴权**，只靠"只听 `127.0.0.1`"来保护。绝对不要把它映射到局域网或公网。
- 含密钥的两个接口（`/api/settings`、`/api/credentials`）单独把跨源限制收紧到了 `http://127.0.0.1:3300`，其它接口是宽松的——这是防"你随手打开的某个网页偷偷读你的 Key"。

### 7. 「模块开关 & API 配置」面板（9 个开关 + 4 类 Key）

**它是什么**
控制台里的一块面板（新手启动器 3400 的第 2 步是同一个东西的另一套界面）。左边九个勾选框，右边四行 Key 输入框。

**九个开关，分两组**

本地服务：

| 开关 | 作用 |
| --- | --- |
| QQ 桥接（3100） | 把 DSH 接到你的 QQ 上才会自动回消息 |
| SnowLuma 网关（5099） | QQ 协议网关，桥接靠它说话 |
| 抖音自动化（`scripts/douyin`） | 接管本机浏览器刷视频 / 发私信 |
| 手机操控（`tools/phone`） | ADB + 视觉；关掉后不会再去连手机 |

DSH 里的 MCP 工具：

| 开关 | 作用 |
| --- | --- |
| QQ 工具（snowluma-safe） | 让助手能收发 QQ 消息 |
| 宿主信息（snowluma-host） | 让助手能启停 SnowLuma 网关 |
| 联网搜索（web-search-safe） | 让助手能搜索网页 |
| 共享记忆（shared-memory） | 让助手读写跨会话记忆文件 |
| 语音（tts-voice · 卡上未带模型） | 语音合成，需要一个很大的本地模型；随身卡默认不带 |

**四类 Key**

| 变量名 | 面板上的名字 | 干什么用 |
| --- | --- | --- |
| `COCO_KEY` | 视觉 / 多模态 API Key | 手机读屏、看截图；没有它「手机操控」直接不可用 |
| `OPENAI_API_KEY` | OpenAI API Key | 可留空；填了会作为视觉/模型的兜底 |
| `COCO_API_KEY` | 模型通道 Key（COCO） | 助手主模型走这条；留空则用 DSH 自己的凭据文件 |
| `COCO233_API_KEY` | 模型通道 Key（备用线路） | 可选，第二条线路，主线路限流时顶上 |

**解决什么痛点**
以前"关掉一个用不上的工具"要改 yml 缩进，"换一个 Key"要找三个文件。现在勾一下、填一下、点保存，剩下的事脚本干。

**怎么用**

1. 勾掉不想用的模块（比如卡上没带语音模型，就把「语音」勾掉）。
2. 在右列填 Key。**留空表示"不修改"**，不是"清空"。
3. 点「保存配置」。
4. MCP 类开关改了之后，**重启 DSH 才生效**（面板上就写着这句）。

**你会看到什么**

- 勾选状态保存后刷新页面还在。
- Key 回读时是打码的，形如 `sk-d…3456`（前四位 + 省略号 + 后四位）；太短的直接显示 `***`。
- 保存 MCP 开关时，`portable-strip.txt` 会被重写（两行固定注释 + 每个被关掉的模块一行），然后立刻跑一次 repath 把配置真正改掉。控制台找这份清单的规则是「`console\` 目录的上一级」，找 repath 的规则是「同一级或 `portable\` 子目录」——在仓库里两者都落在仓库根，在卡上请确认这两个位置是同一个目录。

**坑与边界**

- **勾掉 = 真删除**。它不是你界面上藏一下，而是把对应配置块从 yml 里摘掉，工具会从这个助手的工具列表里彻底消失。
- 在**源码仓**里跑时，因为没有 `.dsh\profiles`，它只会写清单不写配置，会明确提示"本栈没有 .dsh/profiles，已跳过改写"。
- 面板改的是 `console\panel.config.json`（这个文件不入库、`.gitignore` 里有）。Key 是明文存在里面的，所以这个文件别外传。
- 有一个跨源放宽（`access-control-allow-origin: *`）是为了方便你在别的端口调试时不被浏览器拦。仅当它只听 `127.0.0.1` 时才安全；一旦暴露到网络，这个放宽就是漏洞。

### 8. 手机操控（`tools/phone/`）

**它是什么**
两个东西：`tools/phone/adb.sh`（一个 bash 封装，专门治 ADB 掉线）和 `tools/phone/phone-vision.mjs`（612 行的 Node 模块，负责截图、叠网格、问视觉模型、拿节点树、点击、打中文）。

**解决什么痛点**
直接敲 `adb` 有四个绕不过去的坑：①连续快速发命令时 server 状态错乱，报"device not found"；②纯靠视觉模型估坐标，分辨率和状态栏一变就偏几十像素；③中文根本敲不进去（`input text` 只吃 ASCII）；④息屏状态下截图是黑的、或者截出一张残缺的 PNG（只有 360 字节），发给视觉模型就稳定报 `upstream_error`。

这套代码对每个坑都有对应解法：

| 坑 | 解法 |
| --- | --- |
| ADB 掉线 | 每次调用先探活，失败了 `kill-server` + `start-server`，最多重试 3 轮；命令串行化执行，不并发 |
| 坐标不准 | 视觉只用来"理解这是哪个按钮"，真正的坐标从 UI 节点树里取控件中心 `cx/cy` |
| 中文输入 | 装 ADBKeyboard 输入法，把文字 base64 编码后广播进去 |
| 息屏 / 截图坏 | 先查屏幕状态；截图后校验 PNG 头尾，坏图立刻重截 |
| 重复调用太贵 | 用截图 md5 做缓存指纹，画面没变就直接返回上次结果（视觉调用一次至少 6 秒） |

**怎么用**

前置：手机开「开发者选项 → USB 调试」，插线，手机上点「允许」。无线调试的话：

```bat
adb pair <手机IP>:<配对端口> <6位配对码>
adb devices
```

`adb devices` 里能看到 `xxx._adb-tls-connect._tcp` 那条（无线）或一串 USB 序列号。注意序列号和状态之间是 **Tab**，不是空格——脚本里如果自己解析，别按空格切。

bash 里用封装：

```bash
source tools/phone/adb.sh
P shell "dumpsys window | grep -i mCurrentFocus"
Pshot /tmp/shot.png
Pui > /tmp/ui.xml
```

Node 里用模块：

```js
import * as P from './tools/phone/phone-vision.mjs';

const st = await P.screenState();          // 先看屏幕是不是亮的
const shot = await P.capture();            // 截图（已裁掉状态栏，且校验过 PNG）
const view = await P.readScreen();         // 叠网格 + 问视觉模型，返回「页面/可点」结构化文本
const nodes = await P.uiNodes();           // 节点树，每项带 cx/cy
const sendBtn = P.findNode('发送');        // 按文字或描述模糊找
await P.tap(sendBtn.cx, sendBtn.cy);       // 点控件中心，不是点视觉估的坐标
await P.inputTextCn('晚上一起吃饭吗');      // 中文走 ADBKeyboard
```

> 说明：`docs/手机操控.md` 里的示例用的是 `ensureDevice / screenshot / grid / typeChinese` 这类更"易懂"的名字，实际导出名以上面这组为准（`screenState / capture / drawGrid / inputTextCn`）。

**你会看到什么**

- `readScreen()` 返回的是固定格式的文本，大概长这样：

```
页面：微信聊天
列表：最近会话 12 条
时间：21:08
电量：73%
可点：发送(860,2320)、输入框(540,2280)、返回(72,180)
```

- 打中文成功时，广播命令会返回 `Broadcast completed: result=0`。
- 点击成功没有输出，但下一次截图画面变了——这也是为什么"每次操作后必须重新截图"。

**坑与边界**

- **没有视觉 Key 就连模块都加载不了**：`phone-vision.mjs` 在加载时就会抛「缺少视觉 API Key」。因为它是 ESM，`import` 那一刻就检查。
- 一次视觉调用至少 6 秒，这是实测下限：降采样没用（小字会认错），换小模型精度直接崩，唯一有效的提速是"别重复调用"（靠 md5 缓存）。
- 裁状态栏需要 `ffmpeg`。找不到会抛「找不到 ffmpeg，无法裁剪状态栏」。裁的原因很实在：状态栏的时间和电量每秒都在变，不裁的话缓存永远命中不了。
- 视频类、游戏类这种自绘界面的 App 没有可读节点，只能退回"网格 + 视觉坐标"。精度会明显下降，点了可能偏。
- `inputText` 只能打 ASCII；中文必须用 `inputTextCn`。打完中文**不要立刻切输入法**，会丢字，保持约 30 秒。
- `dumpUi()` 裸跑要 3～5 秒，别在循环里高频调用。
- 隐私提醒：读屏等于把你手机上的一切都截给模型看了。建议用备用机、限定在某几个 App、截图用完即清。

### 9. 抖音自动化（`scripts/douyin/`）

**它是什么**
三个脚本，共同点是**通过 CDP（Chrome 调试协议）接管你本机已经登录的浏览器**，地址固定是 `http://127.0.0.1:9222`。

| 脚本 | 干什么 |
| --- | --- |
| `browse.mjs` | 刷推荐流，抓标题/作者/时长/点赞，逐步截图，结果写 `./feed/items.json` |
| `dm.mjs` | 操作私信：`list` 列会话、`open "某位好友"` 打开、`send "某位好友" "话"` 发送 |
| `auto-share-watch.mjs` | 盯着"自主观看"状态，一旦开始刷视频就把当前作品分享给指定好友（每轮只发一条，有回执不重发） |

**解决什么痛点**
直接调抖音的网页接口？不行：接口带签名和设备指纹，参数对不上直接拒。用无头浏览器？也不行：无头环境的指纹太明显，容易被识别。唯一的办法是用**你自己那只已经登录、有完整指纹的浏览器**。

代价也很直接：这个浏览器必须开着，而且 9222 这个调试端口不能同时被别的东西占用。

**怎么用**

第 1 步，用调试端口启动浏览器（Edge 示例）：

```bat
"C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe" --remote-debugging-port=9222 --user-data-dir="%USERPROFILE%\.dsh\douyin-browser\cli-profile" https://www.douyin.com/
```

三个细节别漏：端口必须是 `9222`（脚本里写死了这个常量）；`--user-data-dir` 要独立，不然会和你日常浏览器的配置打架；第一次要**手动登录一次**。

第 2 步，跑脚本：

```bat
node scripts\douyin\browse.mjs 5 2.5
node scripts\douyin\dm.mjs list
node scripts\douyin\dm.mjs send "示例好友" "这个视频挺有意思"
node scripts\douyin\auto-share-watch.mjs --to "示例好友" --interval 20000 --dry
```

`auto-share-watch.mjs` 的参数：`--to 好友`（发给谁，可省略）、`--interval 毫秒`（默认 20000）、`--once`（只跑一轮）、`--dry`（只打印不发）、`--log 文件`（写到指定日志）。

**你会看到什么**

- `browse.mjs` 会打印每一条的标题和作者，并在 `scripts\douyin\feed\` 下留一串 `step-01.png` 之类的截图。
- `dm.mjs list` 打印会话行的名字；`send` 成功后关键操作都有截图留档。
- `auto-share-watch.mjs` 打印它读到的状态和每一轮的动作；有 PID 文件做单实例保护，重复启动会说「已有实例 pid=… 在运行，退出」。

**坑与边界**

- 浏览器没开 9222，所有脚本都会报 `fetch failed`；页面列表为空则多半是没登录（或你用了无头模式）。
- 找不到会话行：昵称必须和界面上显示的**完全一致**，先 `list` 看一遍再填。
- 输入框找的是 `contenteditable` 元素，抖音改版就可能失效。
- **`auto-share-watch.mjs` 依赖同目录的 `share-latest.mjs` 才能真正分享**，而本仓库里没有这个文件（它在真正的卡上）。缺它的时候，自动分享会直接报错——这不是坏了，是缺件。
- 同一个调试端口不能跑别的调试任务，会互相抢。
- 合规边界（文档里写明的）：只操作本人账号、只分享公开作品的链接、低频；不主动点赞、评论、关注。

### 10. 厂商 ROM 适配（以 MagicOS 为例）

**它是什么**
`docs/MagicOS适配实录.md` 是一份实测记录：在一台装了厂商定制系统（MagicOS 11 / Android 17）的旗舰机上，一个第三方 App 想监听微信通知，到底会撞上什么。

**解决什么痛点**
"我代码明明写对了，服务也显示 enabled，为什么就是收不到通知？"——因为拦截不在你的代码里，在系统里。

**实测到的三件事**

1. **系统层直接拦绑定**。日志里是这两行：

```
W ActivityManager: Service starting has been prevented by iaware or trustsbase
W NotificationListeners: Unable to bind notification listener service:
```

服务是 enabled 的，但永远不会 connected。手动去设置里把开关打开，也照样不生效。

2. **冻结连前台进程都不放过**。冻结日志长这样：

```json
{"freeze_pkg":"<你的包名>","freeze_uid":10475,"proxy":1,"is_front":1, ...}
```

`is_front:1` 意思是"在前台"，照样冻。同一时刻它还冻了 GMS、输入法、系统设置和天气。

3. **adb 层豁免全部无效**。这条最反直觉，实测数据是：

| 手段 | 结果 |
| --- | --- |
| `cmd deviceidle whitelist +<包名>` | 写入成功，oom adj 只从 1001 降到 701，照样冻 |
| `cmd appops set <包名> RUN_ANY_IN_BACKGROUND allow` | 成功，无效 |
| `cmd app_hibernation get-state <包名>` | 返回 false —— 说明这不是标准休眠，是厂商私有冻结 |
| `cmd IAwareCMSService help` / `IAwareSdkService help` | `No shell command implementation` |

结论：**这不是 root 能改的开关**。

**怎么用（用户必须动手的部分）**

这部分必须说清楚：哪些是 App 能做的，哪些只能你做。

- App 能做的：检测自己有没有被冻（对比时间戳、检测服务是否断开）、断线重连、把可执行的设置步骤用文字推给用户、不要把已经显示的通知清空。
- App **做不到**的：绕过系统绑定拦截、绕过 `freeze_pkg`、用 adb 给自己开后门。

所以要你在系统 UI 里加白名单，三步：

1. **手机管家 → 应用启动管理 → 找到这个 App → 关掉"自动管理" → 手动管理 → 自启动 / 关联启动 / 后台活动 全开。**
2. **设置 → 电池 → 更多电池设置 → 应用耗电管理 → 这个 App → 不优化。**
3. **最近任务里把这个 App 下拉锁定；再给它开"允许通知"和"悬浮通知"。**

**同样三步也要给微信做一遍。** 不加的话，微信退到后台大约 9 秒就被冻住再解冻，循环往复，表现就是"有时候必须手动点开微信才收得到消息"。

**你会看到什么**
加完白名单后，`adb shell dumpsys activity processes | grep -A5 <包名>` 里能看到 `curProcState` 是前台服务态、oom adj 在 200 左右（说明前台服务真生效了）。如果 adj 还是 700+ 且 `cached=true`，随时会被清掉。

**坑与边界**

- **FGS 和 JobScheduler 挡不住这个。** 前台服务 + 定时任务 + 定时重绑只能提高存活率，打不过系统的 `freeze_pkg`。别指望在 App 里"对抗"它。
- **别用气泡。** Android 的气泡要求宿主 Activity 声明兼容，微信没有，系统会把微信全屏开在泡泡底下，泡泡壳里只剩一个白色跳板，"点开是透明框框、不能回复"。正确做法是用 `contentIntent` 直接跳到会话，不要调 `.setBubbleMetadata(...)`。
- **快捷回复按钮做不出来。** `Notification.CarExtender` 在 API 33 已废弃；微信也不给带 `RemoteInput` 的 actions——实测每条真实消息 `actions=null/empty`、`carExt=null`。第三方只能拿到微信愿意交出来的东西。
- 这套结论来自**某一台具体机型的具体系统版本**，别的厂商（小米、OPPO、vivo）机制不同，别照抄结论，照抄排查方法。

**五条排查命令**（出问题时按顺序跑）

```bat
adb shell dumpsys notification | grep -A3 "Notification listeners"
adb shell dumpsys activity services <包名>
adb shell logcat -v time | grep -iE "freeze_pkg|iaware|trustsbase|hibernation"
adb shell dumpsys activity processes | grep -A5 <包名>
adb shell run-as <包名> cat files/diag.log
```

### 11. API Key 与模型通道

**它是什么**
这个项目里有四条独立的"调用链"，每条要一种 Key：

| 调用链 | 用哪个变量 | 谁在用 |
| --- | --- | --- |
| 手机读屏（视觉） | `COCO_KEY`（备用 `OPENAI_API_KEY`） | `tools/phone/phone-vision.mjs` |
| 助手主模型 | `COCO_API_KEY`（或 DSH 自己的凭据文件） | DSH 本体 |
| 备用线路 | `COCO233_API_KEY` | 控制台的通道切换 |
| 官方通道 | `OPENAI_API_KEY` | 只走官方时用 |

**解决什么痛点**
一个 Key 打天下在这里行不通：视觉调用和文本调用往往是不同模型、不同价格、不同限流。分开放，哪条挂了换哪条，不至于全套瘫掉。

**怎么用**

1. **填在哪里**：三处任选其一，效果一样——新手启动器第 2 步 / 控制台 3300 的面板 / 手改 `console\panel.config.json` 的 `settings.env`。面板保存后写进 `panel.config.json`，属于"本机私有"，不入库。
2. **怎么验证可用**：在**新手启动器（3400）**第 2 步，每个 Key 输入框旁边有个「测试」按钮（控制台 3300 的 Key 面板没有这个按钮，所以验 Key 统一去启动器）。它实际是向 `${base}/models` 发一个带 `Bearer` 的 GET，12 秒超时。
3. 改完 **重启 DSH**（面板改的 Key 只在"新启动的进程"里生效）。

**你会看到什么**

- 测试成功：`可用（https://api.cocoapi.top/v1，返回 N 个模型）`。
- 测试失败：`HTTP 401：...`（Key 错）或 `连不上 ...：超时`（网络/地址问题）。
- 面板回读：`sk-d…3456` 这种打码样子（前四位 + 省略号 + 后四位），完整值不会再显示；要换就整条覆盖输入框。（只有控制台「🔑 登录密钥」那三项——SnowLuma 密码、桥接 token、OneBot token——才有 👁 显示 / 📋 复制 按钮。）

**坑与边界**

- **留空 = 不修改**，不是"清空"。要真清空，得去 `panel.config.json` 里删掉那个字段。
- 面板里填的 Key 优先级**高于**系统环境变量（子进程的环境 = 系统环境 + 面板配置，面板赢）。
- `panel.config.json` 里 Key 是明文的。这个文件在 `.gitignore` 里，但你手动备份、发群里就漏了。
- 视觉 Key 和模型 Key 别混用：拿文本 Key 去调视觉接口，会报"模型不支持图像输入"。
- 402/429 不是 Key 错，是额度用完或被限流，换备用线路。

### 12. 新手启动器（`start-gui.bat`，3400 端口）

**它是什么**
仓库根目录的 `start-gui.bat` + `launcher\server.mjs` + `launcher\index.html`。给"第一次用、不想碰命令行"的人一个「双击 → 浏览器里点几下」的入口。只用 Node 内置模块，**不需要 `npm install`**（卡上没网也能跑）。

页面是四步导航：**1 先体检 → 2 填 Key · 选模块 → 3 启动 · 看日志 → ? 出问题怎么办**。

**解决什么痛点**
不用记端口、不用记命令行、不用猜"我是不是缺了什么"。体检会把 8 项一次性列出来，红的绿的黄的，哪项不行直接给修复建议。

**怎么用**

双击 `start-gui.bat`。它会自己找 Node（优先卡上的 `node\node.exe`，其次上级目录，最后 `where node`），然后起服务并自动打开浏览器。

**8 项体检都是什么**

| 项 | 查什么 | 不合格会怎样 |
| --- | --- | --- |
| Node 运行时 | 版本号，要求主版本 ≥ 20 | 红：装 Node LTS |
| DSH 本体 | `bin.js` 在不在 | 红：把 `dsh-workspace` 放卡根 |
| DSH 配置目录 | 有没有 `.dsh\profiles` | 黄：你在仓库里跑，能用但改不了配置块 |
| 工作目录 | `workspace` 在不在 | 黄：助手没法读写文件 |
| 可写盘 | 试着写一个 `.write-probe` 再删掉 | 红：卡被写保护，或用管理员运行 |
| DSH 端口 3080 | 被占还是空闲 | 蓝（idle）：未占用，正常 |
| 控制台端口 3300 | 同上 | 同上 |
| API Key | 四个里有没有填了任意一个 | 黄：能开界面但助手调不动模型 |

只要没有红的，页面就认为"可以启动"。

**你会看到什么**
顶部一串彩色小圆点和说明文字；第 3 步有「一键启动」「只启动 DSH」「在浏览器打开 DSH」「打开控制台」「全部停止」几个按钮，加一个实时滚动的日志窗口。

**坑与边界**

- 只想换端口：`node launcher\server.mjs --port 3401`，或双击 `start-gui.bat --port 3401`。
- 不想让它自动开浏览器：加 `--no-open`。
- 关掉黑窗口只是关启动器，**已经跑起来的 DSH 不会被停**。
- 它只监听 `127.0.0.1`、**没有鉴权**，和 3300 一样，绝不能映射出去。
- 它不是"常驻管理器"，重活还是控制台 3300 干。两边共用同一份 `console\panel.config.json`，在哪儿改都一样。

## 四、API 服务推荐：CocoAPI

### 它是什么

CocoAPI 是一个 **OpenAI 兼容的聚合中转**，地址是 `https://api.cocoapi.top/v1`。

"OpenAI 兼容"这句话很关键：意思是它的接口格式和 OpenAI 官方一模一样（`/v1/chat/completions`、`/v1/models`），所以任何按官方协议写的代码，只要把 `baseURL` 一改就能用它。本项目里两处就是这么写的：

- `tools/phone/phone-vision.mjs` 顶部：`export const COCO_BASE = 'https://api.cocoapi.top/v1/chat/completions';`
- `launcher/server.mjs` 的 Key 定义里，每个 Key 都带一个 `base: 'https://api.cocoapi.top/v1'`。

### 为什么新手用这类中转更省事

- **不用国际信用卡**：官方要外币卡，很多人卡在第一步。中转一般支持支付宝/微信。
- **不用科学上网**：中转的域名国内直连。
- **一个 Key 多模型**：想换模型只改一个名字，不用再注册一家。
- **有备用线路**：主线路限流了换一条，这个项目本身就留了 `COCO233_API_KEY` 这个位置。

### 怎么拿 Key、怎么填

1. 到它的网站注册账号，在控制台里生成一个 API Key（一般长这样：`sk-xxxxxxxx`）。
2. 打开新手启动器或控制台，找到「API Key」区。
3. 按用途填到对应的那一行：

| 你要做的事 | 填哪一行 | 变量名 |
| --- | --- | --- |
| 让助手能看手机屏幕 | 视觉 / 多模态 Key | `COCO_KEY` |
| 让助手能正常对话 | 模型通道 Key | `COCO_API_KEY` |
| 主线路不稳时兜底 | 备用线路 Key | `COCO233_API_KEY` |
| 你有官方 Key | OpenAI 官方 Key | `OPENAI_API_KEY` |

4. 点「保存」，再点这个 Key 旁边的「测试」，看见 `可用（...，返回 N 个模型）` 就成了。

> 本文档里所有 Key 一律写成 `sk-xxxxxxxx` 占位。**任何真实 Key 都不要写进文档、截图、聊天记录。**

### 模型怎么选（按场景）

| 场景 | 需要什么能力 | 建议选什么样的模型 | 备注 |
| --- | --- | --- | --- |
| 手机读屏（`phone-vision.mjs`） | **必须支持图像输入**，能看懂界面文字和小字 | 多模态视觉模型，宁可强一点 | 一次调用至少 6 秒；换小模型精度会崩，省这点钱不值 |
| 助手主对话 / 工具调用 | 支持 function calling、长上下文 | 代码与工具调用能力强的通用模型 | 这是 `COCO_API_KEY` 那一条，用得最多 |
| 长文档、整仓分析 | 大上下文窗口 | 上下文大的型号 | 便宜的小窗口模型会截断，结果不可靠 |
| 简单批处理（分类、抽取） | 便宜、够用 | 小模型 | 别拿它做视觉，会认错字 |
| 备用线路 | 能顶上就行 | 和主线路同级别 | 通过 `COCO233_API_KEY` 走 |

选模型的土办法：**先拿最强的跑通，确认整条链路没问题，再往下降级**。一上来就挑最便宜的，出了错你分不清是"模型笨"还是"配置错"。

### 换成别的服务商行不行

行。只要满足两点：① 是 OpenAI 兼容协议；② 支持你要用的模型类型（视觉那一步必须支持图像输入）。

- 官方 OpenAI：把 Key 填到 `OPENAI_API_KEY`，base 用 `https://api.openai.com/v1`，控制台里点「切到官方」。
- 其它兼容中转：把 base 改成它的地址（启动器/控制台的 Key 定义里可以覆盖 `base`），Key 照填。
- 自建（vLLM、one-api 之类）：同样只要有 `/v1/chat/completions` 和 `/v1/models` 就行。

改 `COCO_BASE` 的位置：`tools/phone/phone-vision.mjs` 顶部那行常量。注意那个常量**是完整路径**（带 `/chat/completions`），和 base 不是一回事，别混。

## 五、Q&A

### 安装环境

**Q：我这台电脑是 Win7，能用吗？**
**A：** 不能。要求 64 位 Windows 10 或 11。
> 原因：Node 22 和 DSH 本体都不再支持 Win7，硬跑会在启动阶段就崩。

**Q：一定要自己装 Node 吗？**
**A：** 看情况。① 有随身卡：不用，卡上自带 `node\`；② 只有仓库：要装，去 nodejs.org 下 LTS（22.13 以上），装完重开终端验 `node -v`。
> 原因：`start-dsh.bat` 会优先用卡上的 node，找不到才用系统 PATH 里的。

**Q：需要装 Python 吗？**
**A：** 不需要。这个项目的主体全是 Node。语音引擎那边用 Python，但随身卡默认不带语音，所以不装也能跑。
> 原因：Python 的虚拟环境（venv）里存的是绝对路径，换了机器就废，所以便携卡刻意不搬它。

### 启动失败

**Q：双击 `start-dsh.bat`，黑窗口一闪就没了。**
**A：** 三步：① 右键那个 bat → 编辑，看它最后停在哪一步；② 常见就是 `node\` 或 `dsh-workspace\` 没拷全，重新拷一遍；③ 在终端里手动跑，报错就留在屏幕上了：

```bat
cd /d E:\DSH
start-dsh.bat
```

> 原因：双击时窗口关闭得比你看得快，只有从命令行启动才能看到真实报错。

**Q：窗口停住了，屏幕上有个 `[X]`。**
**A：** 看 `[X]` 后面那半句：`没找到 node` → 拷 `node\` 目录；`没找到 bin.js` → 拷 `dsh-workspace\`；`没找到 .dsh` → 拷 `.dsh\`。三个都是"文件不全"，不是代码问题。

**Q：双击后有窗口，但好几分钟没动静。**
**A：** 正常，等。USB 卡首次启动要读几万个插件小文件，10～60 秒都算正常，SD 卡更慢。
> 原因：卡是随机读性能最差的介质，`node_modules` 又是海量小文件。

### 端口占用

**Q：提示 3080 端口被占用。**
**A：** 三步：① 先点「全部停止」；② 查是谁占的：

```bat
netstat -ano | findstr :3080
```

③ 拿最后一列 PID 去任务管理器结束那个 `node.exe`。或者干脆换端口：`start-dsh.bat --port 3081`。

**Q：3300 或 3400 打不开。**
**A：** 同样先查 `netstat -ano | findstr :3300`。控制台可以换端口启动；启动器用 `--port 3401`。

### DSH 打不开

**Q：浏览器打开 `http://127.0.0.1:3080` 显示 401 或"authentication required"。**
**A：** 这不是错误，是**必须带 token**。点启动器/控制台里的「在浏览器打开 DSH」，它会给你带 `?token=...` 的完整地址。别手输纯地址。
> 原因：DSH 每次启动生成一次性 token，地址里不带就被拒。

**Q：页面能开，但一片空白 / 一直转圈 / 工具全是红的。**
**A：** ① 换电脑后工具全红 → 先跑 `node portable\portable-repath.mjs`；② 只有部分红 → 跑 `node portable\portable-verify.mjs` 看是哪一组；③ 一直转圈 → 看那个黑窗口最后几行，通常有明确报错。

### 401 鉴权

**Q：token 到底是什么？我要记住它吗？**
**A：** 不用记。每次启动都会变，用「打开 DSH」按钮拿新的就行。

**Q：换个浏览器/开隐私模式又要 token 了。**
**A：** 正常，重新点一次「打开 DSH」。

### Node 缺失

**Q：`node -v` 提示"不是内部或外部命令"。**
**A：** ① 装 Node LTS；② **关掉终端重新开一个**（PATH 不会自动刷新）；③ 再验一次；④ 还是不行就重启电脑。
> 原因：环境变量只在新的进程里生效。

### SD 卡盘符变化

**Q：换了台电脑，工具全部变红，报"文件不存在"。**
**A：** 卡根跑一次：

```bat
cd /d F:\DSH
node portable\portable-repath.mjs
```

然后重新双击 `start-dsh.bat`。
> 原因：配置里存的是绝对路径，盘符从 `E:` 变 `F:` 就全废了。repath 就是把它们按当前盘符重写。

**Q：能不能不每次跑 repath？**
**A：** 不能省，但也不用你手动——`start-dsh.bat` 每次启动都会自动跑一遍。手动跑只是"排查时用"。
> 原因：MCP 的启动命令必须是绝对路径，没有相对路径这条路。

### exFAT 与 junction

**Q：为什么不能把 `node_modules` 做成快捷链接（junction）省空间？**
**A：** exFAT 不支持符号链接和 junction，拷到卡上会直接失效。项目的做法是把原来三个链接**实体化**成真目录。
> 原因：`portable-verify.mjs` 第 7 组专门扫这个，发现链接就报错。

**Q：往卡上复制时提示"符号链接无法复制"。**
**A：** 用 `robocopy` 加 `/SL` 或干脆跳过那些目录，也可以用项目自带的 `sync-to-card.ps1`（它已经处理好了）。复制完跑一次 verify 确认。

### 权限不足

**Q：写文件失败，或者提示"只读"。**
**A：** ① 确认卡的写保护开关没拨到 lock；② 换一个目录试写一个文件；③ 用管理员身份运行一次；④ 启动器第 1 步的"可写盘"那项如果是红的，就是这个问题。

**Q：杀毒软件报毒、把 `node.exe` 删了。**
**A：** 加白名单/信任目录，然后把 `node\` 重新拷一遍。
> 原因：`node.exe` 是未签名的独立运行时，启发式扫描经常误报。

### Python 环境

**Q：脚本报"找不到 python"或"模块不存在"。**
**A：** 这个项目的主体不需要 Python。只有语音引擎（GPT-SoVITS）需要，而随身卡默认不带语音。想用语音就按 `docs\便携卡使用说明.md` 把 `gpt-sovits\` 和 `rvc\` 拷回卡上，并从 `portable-strip.txt` 里删掉语音那一行。

### ADB 连不上

**Q：`adb devices` 是空的。**
**A：** ① 手机上开「开发者选项 → USB 调试」；② 插线后在手机上点「允许」；③ 重来一次：

```bat
adb kill-server
adb start-server
adb devices
```

④ 无线的话要先 `adb pair <手机IP>:<配对端口> <6位配对码>`。

**Q：无线调试怎么连？**
**A：** 手机和电脑连同一个 Wi-Fi → 手机「无线调试」→ 用配对码 `adb pair` → 之后 `adb devices` 里会出现 `xxx._adb-tls-connect._tcp` 那条。脚本会自动优先用它。
> 原因：`phone-vision.mjs` 解析 `adb devices` 时按 **Tab** 切分而不是空格，因为 mDNS 序列号里可能带空格。

**Q：我有两台手机，怎么指定？**
**A：** 设环境变量：

```bat
set PHONE_SERIAL=你的设备序列号
```

或 `set ADB_BIN=` 指向你自己的 adb 路径。

### 手机无响应

**Q：刚才还能用，突然所有命令都超时。**
**A：** `adb kill-server` 然后 `adb start-server`，再试一次。项目里的 `adb.sh` 和 `phone-vision.mjs` 已经内置了这个重试（最多 3 轮 + 重连等待），你手敲的时候也照这个套路来。
> 原因：连续快速发多条命令时 adb server 的状态会错乱，不是线材问题。

**Q：截图全黑，或者截图失败。**
**A：** ① 先 `adb shell dumpsys power | grep mWakefulness` 看是不是息屏；② 亮屏后再截；③ 截出来的 PNG 只有几百字节说明是坏图，重截一次。
> 原因：息屏时 `screencap` 会返回黑图或残缺数据；残缺数据发给视觉模型会稳定报 `upstream_error`。

### 通知类问题

**Q：通知监听服务开了，但一条通知都收不到。**
**A：** 这台机器十有八九是厂商定制系统（MagicOS / EMUI 这类）。三步：① 手机管家 → 应用启动管理 → 关自动管理 → 自启动/关联启动/后台活动全开；② 电池 → 应用耗电管理 → 该 App → 不优化；③ 最近任务下拉锁定。**微信也要同样加一遍**。
> 原因：系统层拦了 `NotificationListenerService` 的绑定，日志是 `has been prevented by iaware or trustsbase`；adb 层白名单实测无效（详见 `docs/MagicOS适配实录.md`）。

### 抖音登录掉线

**Q：抖音脚本报 `fetch failed`。**
**A：** 说明 9222 端口上没人。按第 9 节那条命令重新用 `--remote-debugging-port=9222` 启动浏览器，并确认已经登录抖音。

**Q：`dm.mjs` 说找不到会话。**
**A：** 先 `node scripts\douyin\dm.mjs list` 看它实际读到的名字，然后**一字不差**地填进去（包括表情、空格）。

**Q：`auto-share-watch.mjs` 报找不到 `share-latest.mjs`。**
**A：** 正常，本仓库里不带这个文件，它在真正的随身卡上。没有它就用 `browse.mjs` + `dm.mjs` 手动做。

### Key 无效或额度

**Q：在启动器里点「测试」返回 401。**
**A：** ① 确认 Key 复制完整（首尾没漏字符）；② 确认填对了行（视觉 Key 填到视觉那行）；③ 重新保存并重启一次。

**Q：返回 402 或 429。**
**A：** 不是 Key 错：402 是余额/额度，429 是限流。① 去服务商后台看余额；② 换备用线路（`COCO233_API_KEY`）；③ 等一会儿再试。

**Q：填了 Key，助手还是说没配模型。**
**A：** 面板改的 Key 只在**新启动的进程**里生效。改完必须重启 DSH。

### 模型幻觉

**Q：助手说它做了某件事，但其实什么都没发生。**
**A：** 别信"我做了"，看证据：让它把命令输出贴出来，或直接看日志/文件有没有变。这个项目所有关键操作都有日志或回执。
> 原因：模型只能看到自己发出的调用，看不到调用是否真的落地。

**Q：它回了一句"针对某条消息"的话，但那条消息不存在。**
**A：** 这是手机读屏缓存/指纹设计要解决的问题。`phone-vision.mjs` 用**截图 md5**做缓存指纹，就是因为它早期用 Activity hash，感知不到同页内容变化，会基于不存在的消息回复。如果还遇到，先 `cacheClear()` 再重试。

### 卡变慢

**Q：卡越用越慢，启动从 20 秒变成两分钟。**
**A：** ① 清 `tmp\` 和日志（`*.log` 会一直长）；② 抖音的 `feed\` 截图目录会堆很多 PNG；③ 别在卡上跑 `npm install` / `pnpm install`。
> 原因：exFAT + 小文件 + 海量 `node_modules` 是随机读写灾难。

### 换电脑

**Q：换电脑需要重新配什么？**
**A：** 只用做两件事：①（可选）`node portable\portable-repath.mjs` —— 其实 `start-dsh.bat` 会自动跑；② 重新拿一次带 token 的地址。Key、记忆、人格都跟着卡走，不用重配。

**Q：能不能把整个卡直接给别人用？**
**A：** 能，但先想清楚：卡上有明文凭据、有聊天记忆。要给，就先把 `.dsh\.credentials.yaml` 和 `console\panel.config.json` 清掉。

### 卸载与清理

**Q：怎么彻底卸载？**
**A：** 这个项目不写注册表、不写系统目录，删目录就行。三步：① 关掉所有黑窗口（DSH / 控制台 / 桥接）；② 删掉卡上的 `DSH\` 整个目录；③ 如果设过环境变量（`DSH_HOME`、`COCO_KEY` 等），在系统设置里删掉。
> 原因：它只用 `DSH_HOME` 指向卡上目录，从不碰 `%USERPROFILE%\.dsh`（除非你自己设了）。

**Q：卡上哪些文件是隐私？**
**A：** `.dsh\.credentials.yaml`（明文凭据）、`.dsh\sessions` 和 `storages`（对话记录）、`console\panel.config.json`（API Key）、`workspace\shared\` 下的记忆文件、抖音的浏览器 profile（登录态）。这几样别外传。

### 术语表

| 词 | 一句话解释 |
| --- | --- |
| **agent** | 会自己决定"下一步做什么"的 AI，不只是回话，还会调用工具去动手 |
| **MCP** | 一种让 AI 调用外部工具的通用协议；每个 MCP 就是一个能被调用的工具服务 |
| **cordis.patch.yml** | DSH 的配置补丁文件，MCP 工具都在这里注册（`id` / `command` / `args`） |
| **repath** | 本项目自己的词：把配置里的绝对路径按当前盘符重写一遍 |
| **幂等** | 同一操作跑一遍和跑十遍结果一样；这里指 repath 值没变就不写盘 |
| **strip（裁剪）** | 用一个文本清单声明"哪些配置块整块删掉"，启动时自动应用 |
| **CDP** | Chrome DevTools Protocol，浏览器对外开放的调试协议，能读页面、模拟按键、截图 |
| **无头浏览器** | 没有界面的浏览器。指纹明显，容易被网站识别，所以这个项目刻意不用 |
| **ADB** | Android Debug Bridge，电脑跟安卓手机说话的命令行工具 |
| **uiautomator** | 安卓自带的界面树导出工具，能拿到每个控件的文字和坐标 |
| **contenteditable** | 网页里"可以打字的区域"，抖音私信输入框就是它 |
| **FGS** | Foreground Service，前台服务；有常驻通知那种后台服务 |
| **JobScheduler** | 安卓的定时任务调度器，省电策略下会被推迟 |
| **freeze_pkg** | 厂商 ROM 的私有冻结机制，日志字段名，冻结时会打印它 |
| **iaware / trustsbase** | 华为系 ROM 里做后台管控的两个系统组件，日志里常一起出现 |
| **junction** | Windows 的目录联接（软链接的一种），exFAT 不支持 |
| **exFAT** | U 盘/SD 卡常用文件系统，跨平台好用，但没有权限控制、不支持链接 |
| **token** | 一次性的访问凭证，DSH 界面地址里那串 `?token=...` |
| **401 / 402 / 429** | 401 = 没凭证或凭证错；402 = 要付费/额度不足；429 = 请求太频繁被限流 |
| **baseURL** | API 的服务地址前缀，比如 `https://api.cocoapi.top/v1` |
| **遥测** | 程序把使用数据回传给开发者。本项目默认**没有**遥测，数据全在本机 |
| **回执** | 操作完成后写下的记录，用来判断"这件事到底做了没有"（如私信分享回执） |

---

**最后一句**：这份手册里所有"你会看到什么"都来自代码和实测记录。如果你照着做看到的东西和这里不一样，先跑一遍 `node portable\portable-verify.mjs`，那份输出比任何猜测都准。
