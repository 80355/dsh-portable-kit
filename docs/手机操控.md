# 手机操控：让 agent 真的去点一台真手机

`tools/phone/` 用 **ADB + 截图 + 视觉模型 + uiautomator 节点树** 组合出一双手。
它不是一个框架，是一组在真机上反复撞墙后收敛出来的实操约定。

---

## 为什么需要这么一套

把「AI 操作手机」做崩的常见原因，按踩坑顺序：

| 坑 | 现象 | 这里的解法 |
| --- | --- | --- |
| 纯视觉坐标点击 | 分辨率/缩放/刘海一变，点偏几十像素 | 视觉只用来**理解语义**，点击坐标一律取自节点树 `cx/cy` |
| USB 掉线 | 连续发命令后 `adb devices` 变空 | `adb.sh` 每次先探活，掉线就 `kill-server; start-server` 重试 3 轮 |
| 中文打不进去 | `adb shell input text 中文` 出来是空白 | ADBKeyboard + base64 广播 |
| 息屏/锁屏/AOD | 截图全黑或只有时钟，AI 以为界面就是这样 | 先查 `dumpsys` 屏幕状态再截图 |
| 截图为空/坏 PNG | 上游模型直接报 `upstream_error` | 截图后校验 PNG 头尾，不合格重截 |
| 节点树滞后 | 屏幕已到私聊页，树还返回消息列表 | 截图与节点树**两个都给**，交叉判断 |
| 视频类 App 自绘 | 节点树几乎没有可用节点 | 退回「网格 + 视觉」，但明确告知精度下降 |

## 前置准备

### 1. ADB

```bash
# Windows：装 platform-tools，或者把 adb 放进 PATH
export ADB_BIN=/path/to/platform-tools/adb.exe   # 可选，默认取 PATH 里的 adb
```

### 2. 连接手机（推荐无线）

```bash
# 手机开启「开发者选项 → 无线调试」，配对一次
adb pair <手机IP>:<配对端口> <6位配对码>
adb devices            # 之后用 _adb-tls-connect 那条，IP 可能变，脚本会自动找
```

两台设备同时连着时必须指定序列号：

```bash
export PHONE_SERIAL=<adb devices 第一列>
```

### 3. ADBKeyboard（中文输入必需）

装开源输入法 ADBKeyboard，然后启用它：

```bash
adb shell ime enable com.android.adbkeyboard/.AdbIME
adb shell ime set    com.android.adbkeyboard/.AdbIME
```

打中文：

```bash
B64=$(printf '%s' "晚上一起吃饭吗" | base64 -w0)
adb shell am broadcast -a ADB_INPUT_B64 --es msg "$B64"
```

打英文/数字可以直接 `adb shell input text hello`，但**不要**用它打中文。

### 4. 视觉模型 Key

```bash
export COCO_KEY=<你的 key>
```

`phone-vision.mjs` 默认走 OpenAI 兼容的 chat/completions 端点，可在文件顶部改
`COCO_BASE` / `VISION_MODEL` 换成任意支持图像输入的模型。

## 核心流程

```
截图  →  叠坐标网格  →  视觉模型读「语义 + 大致位置」  →  uiNodes() 找真实控件  →  tap(cx, cy)
                                                ↘ 找不到控件时才退回视觉坐标（并提示精度下降）
```

### 坐标网格为什么有用

在截图上按固定间距（如 60px）画红色网格线，顶部标 x 刻度、左侧标 y 刻度。
视觉模型于是能回答「发送按钮在 (860, 2320)」而不是「在右下方」——对点击精度是质变级提升。

### 节点树为什么必须与截图一起给

抖音、小红书这类重绘型 App 的 uiautomator 树经常滞后一页。
只用树 → 点到上一页的控件；只用图 → 坐标会偏。两个一起给，模型才能发现「树和图不一致」。

## 常用命令

脚本按函数导出，用 `node -e` 或写个小调用脚本即可：

```js
import * as P from './tools/phone/phone-vision.mjs';

await P.ensureDevice();          // 探活 + 自动重连
const shot = await P.screenshot(); // 截图（含 PNG 校验）
const grid = await P.grid(shot.path);
const nodes = await P.uiNodes();   // 节点树
const node = P.findNode(nodes, '发送');
if (node) await P.tap(node.cx, node.cy);
await P.typeChinese('晚上一起吃饭吗');
```

也可以直接跑 `node tools/phone/phone-vision.mjs` 看内置的主流程示例。

### 重要约束

- **不要**把视觉模型给出的坐标直接用于 `tap`。它读的是「语义」不是像素真值。
- 每次操作后**重新截图**再判断，不要基于上一次的画面连点。
- 屏幕状态未知（AOD/锁屏）时先 `screenState()`，别浪费一次错误截图。

## 故障排查

| 现象 | 处理 |
| --- | --- |
| `adb devices` 空 | `adb kill-server && adb start-server`；仍空就重新配对无线调试 |
| 截图全黑 | 手机息屏/AOD：先点亮再截 |
| 中文变空白 | ADBKeyboard 没启用，或用了 `input text` |
| 视觉模型 `upstream_error` | 截图 PNG 不完整，通常是 `exec-out screencap` 被截断，重截 |
| 点不中 | 检查是否用了视觉坐标；改用节点树 `cx/cy` |
| App 里没有可用节点 | 该页面为自绘（游戏/视频），只能靠网格+视觉，降低期望 |

## 隐私提醒

这一套要读手机屏幕。**屏幕上有你的一切**：聊天、支付、通讯录。
建议：

- 单独用一台备用机或测试机；
- 或对话期间只让 agent 操作指定的 App；
- 截图产物默认落临时目录，用完即删。
