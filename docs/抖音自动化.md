# 抖音自动化：用你自己的浏览器，而不是无头浏览器

`scripts/douyin/` 不给抖音造自动化 API，也不模拟登录。
它做一件更朴素的事：**接管你本机已经登录好的浏览器**，通过 CDP（Chrome DevTools Protocol）驱动真实页面。

---

## 为什么不直接调接口

- 抖音的 Web 接口带签名与设备指纹，模拟成本高、容易失效；
- 无头浏览器指纹明显，账号状态容易异常；
- 而「你本机那个已经登录的浏览器」是最真实的身份，也是最稳的通道。

代价是：**浏览器必须开着**，且不能在同一个调试端口上跑别的东西。

---

## 启动一个可被接管的浏览器

```bat
:: Edge
"C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe" ^
   --remote-debugging-port=9222 ^
   --user-data-dir="%USERPROFILE%\.dsh\douyin-browser\cli-profile" ^
   https://www.douyin.com/
```

Chrome 同理。关键三点：

1. `--remote-debugging-port=9222` —— 脚本默认连这个端口（`BASE` 常量）；
2. `--user-data-dir` 指向**独立**的 profile 目录，不要污染日常浏览器；
3. 首次启动后手动登录一次，之后 profile 会一直保留登录态。

> 注意：如果 DSH 的浏览器插件已经占用了同一个 profile，脚本会检测到并让路——别同时用两个驱动抢一个页面。

---

## 三个脚本

### `browse.mjs` —— 低频、像真人地刷

```bash
node browse.mjs [条数] [每条等待秒]
# 例：node browse.mjs 8 3
```

对每一条视频抓取：标题、作者、时长、点赞数与当前截图，落盘到 `./feed/`。

设计上有意「慢」：每步之间等待 2~3 秒，滚动距离随机，避免连续快速滚动触发风控。

### `dm.mjs` —— 私信

```bash
node dm.mjs list                              # 列出会话
node dm.mjs open "某位好友"                    # 打开会话并读取
node dm.mjs send "某位好友" "这里是想说的话"     # 打开会话并发送
```

实现要点：会话列表在右侧抽屉里，先点「私信」图标 → 等列表渲染 → 按昵称匹配行 → 点进会话 → 找输入框（contenteditable）→ 输入 → 点发送。

### `auto-share-watch.mjs` —— 看完自动分享

```bash
node auto-share-watch.mjs [--to 某位好友] [--interval 20000] [--once] [--dry] [--log 文件]
```

盯住「自主观看」的状态文件，每轮结束把刚看完的作品分享给指定好友。

- 每轮**只发一条**；
- 回执里已经发过的作品不重发（幂等）；
- `--dry` 只打印不发送；
- 浏览器被别的进程占用时直接让路，不抢。

## 稳健性约定

| 约定 | 原因 |
| --- | --- |
| 每次操作前重新枚举页面 | 页面可能被用户手动切换/关闭 |
| 关键操作后截图留存 | 出错时能回看「当时的界面是什么样」 |
| 失败重试而不是死等 | 抖音页面加载是懒的，找不到元素先等 1~2 秒再试一次 |
| 发送类操作记录回执 | 幂等，避免重复打扰同一个人 |
| 不主动点赞/评论/关注 | 除非你自己明确要求，脚本默认不做互动 |

---

## 合规与边界

- 这是**你本人账号**的自动化，不涉及他人账号；
- 私信分享的是公开作品链接，不抓取他人隐私数据；
- 请遵守平台规则与当地法律：批量骚扰、刷量、导流都属于滥用，与本工具无关；
- 脚本默认低频，就是为了别让它变成滥用工具。

---

## 排错

| 现象 | 原因 |
| --- | --- |
| `fetch failed` / 连不上 9222 | 浏览器没开调试端口，或端口被改 |
| 页面列表为空 | 浏览器是「无头」或 profile 未登录 |
| 找不到会话行 | 昵称需与界面显示完全一致；先 `dm.mjs list` 看真名 |
| 输入框找不到 | 抖音用 contenteditable 而非 `textarea`，脚本按 `[contenteditable]` 匹配 |
| 发送后没回执 | 检查 `--log` 路径是否可写 |
